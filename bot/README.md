# Бот автопрохождения зон (Mudlet, «Сфера Миров»)

Нужны [`mapper.lua`](../mapper.lua) и [`antibot.lua`](../antibot.lua) из корня репозитория и поддержка MSDP на сервере.

## Файлы

| Файл | Назначение |
|---|---|
| [botCore.lua](botCore.lua) | Ядро: запись маршрута, правила зон (all/list, kill/aggro/noattack), `.бот ...`, MSDP/промпт, круг зон, статистика |
| [botWalk.lua](botWalk.lua) | Пошаговый проход: ход → ack по VNUM, ресинк, recovery, двери |

| [zones/](zones/) | Записанные маршруты зон (`<зона>.lua`); ставятся в профиль при установке |
| [aliases/bot.lua](aliases/bot.lua) | Алиас `.бот ...` |

| [aliases/botkill.lua](aliases/botKill.lua) | Алиас `botkill` = `sendWithClear(getAttack())` — атака первой цели |
| [tools/install_bot.py](tools/install_bot.py) | Установка/снятие в профиле (`permScript`/`permAlias`) |

| [tests/botHarness.lua](tests/botHarness.lua) | Стенд с заглушками Mudlet API |

Порт jmc-бота `BotCore.js`: бот бежит к клетке входа зоны через `MudMapper`, создаёт экземпляр зоны (`гг !обл созда`), проходит её по записанным клеткам, добивая мобов на пути, и выполняет записанные в комнатах действия.

Модель маршрута: каждый ход помнит ожидаемый VNUM (`msdp.ROOM.VNUM`), поэтому один ход — одна команда и подтверждение комнатой. Если VNUM не совпал (телепорт, сбили с ног), включается recovery: сначала мягкий ресинк по маршруту, затем путь из `generic_mapper` (`getPath`), и всё это тем же пошаговым циклом с добиванием мобов. Закрытая дверь — отдельный случай: бот просто повторяет шаг, дверь открывает профильный триггер.

Состав: `botCore.lua` (ядро, команды, MSDP/промпт, круг зон, статистика), `botWalk.lua` (шаги, ресинк, recovery, двери), `botCombat.lua` (бой по номеру: `botkill`), `botPanel.lua` (плашка), `mapperEchoFix.lua` (патч эха `generic_mapper`), алиасы `aliases/bot.lua`, `aliases/botTrig.lua`, `aliases/botWait.lua`, `aliases/botKill.lua`.

## Как это работает на живом сервере

Снято с работающего профиля через Mudlet MCP (`msdp.ROOM`, буфер, промпты):

- `msdp.ROOM` отдаёт только `VNUM`, `NAME`, `AREA`, `EXITS` — **списка мобов (MOBS) нет**, поэтому содержимое комнаты разбирается из текста, а «моб или предмет» решается по цвету (`prey`-строки) или по фильтру текста.
- Промпт: `11533H 20747M 2298V 91.6636%X 465681C Вых:С(В)ЮЗ> ` (в бою добавляются `[я:хп] [цель:хп]`, `(В)` — закрытая дверь). В этой сборке Mudlet `tempPromptTrigger` не даёт строку промпта, поэтому промпт распознаётся по шаблону в обычном строчном триггере (`Bot.is_prompt_line`) — там же, где и строки комнаты.
- Строку бот берёт **из `matches[2]`** строчного триггера `^(.+)$`, а не из `getCurrentLine()`: в этой сборке Mudlet `getCurrentLine()` читает строку под курсором пользователя (курсор двигают `echo`/debug, а серверное `очистить` очищает буфер) и возвращает литерал `ERROR: invalid line number`, если курсор вне буфера. Из-за этого бот мог терять строку или читать своё же отладочное эхо; теперь это исключено, а `ERROR:`/`Lua:`-строки на всякий случай отсеиваются.
- Блок комнаты: заголовок → `[ Exits: N E S W ]` → строки содержимого → пустая строка → промпт. Между блоками приходят события (`Маленький зайчик припрыгал с севера.`, `Наступил вечер.`, `Олень ускакал на юг.`) — они **не** считаются целями.
- В блоке бывают служебные строки: `[Зона, на север: …]`, `(mapper): Adding open door to the west`, ASCII-карта. Они отфильтровываются.
- Цвета на сервере: мобы **и все игроки** — красный, предметы — жёлтый, описание комнаты — серый, заголовок — светлый циан, выходы — циан, промпт — зелёный. Цвет каждой строки бот читает так: выделяет capture-группу триггера (`selectCaptureGroup(2)` — это вся строка шаблона `^(.+)$`), берёт `getTextFormat().foreground` (`{r, g, b}`) и снимает выделение; `getTextFormat()` читает начало выделения, поэтому цвет не зависит от курсора (fallback для стенда — `selectCurrentLine()`). Дальше `Bot.color_kind` классифицирует по оттенку: красные строки — существа, жёлтые — предметы (`предметов: N` в `.бот цель`), остальные — проза описания. `getFgColor()` и цветовые триггеры Mudlet (`tempColorTrigger`) не используются: вне выделения `getFgColor()` отдаёт мусор (255 у любой строки), а цветовые триггеры срабатывают на весь буфер. Строки `ERROR: …`/`Lua: …` бот на всякий случай игнорирует. Их источник в профиле — `generic_mapper`: `map.echo`/`map.echon` зовут `getCurrentLine()` после `moveCursorEnd`, а в этой сборке Mudlet она читает курсор пользователя; скрипт `MapperEchoFix` подменяет эти функции на безопасное чтение последней строки (`getLastLineNumber` + `getLines`) и сохраняет оригинальный гейт: `map.echo(..., true)` печатает debug-строки только при включённом `map debug` (`map.configs.debug`).
- Атака — **по номеру**, а не по имени: в комнате ты №1, за тобой согрупники, петы, и только потом мобы, которые были здесь до вас. Первый такой моб — `group_count + pet_count + 1`, это и отправляет `botkill` (`sendWithClear(getAttack())`). Имена мобов боту не нужны: `.бот цель` показывает строки комнаты как есть.

## Установка

Автоматически (профиль должен быть открыт в Mudlet, AI-доступ/MCP включён):

```
python3 tools/install_bot.py --dry-run      # план: что и куда ставится
python3 tools/install_bot.py                # установка в активный профиль
python3 tools/install_bot.py --profile sowmud.ru
python3 tools/install_bot.py --uninstall    # отключить элементы бота
```

Скрипт кладёт `BotCore`, `BotWalk`, `BotCombat`, `BotPanel`, `MapperEchoFix` в группу скриптов `ZoneBot` (создаёт её через `permGroup`, элементы включает `enableScript` — Mudlet создаёт их выключенными) и алиасы в одноимённую группу алиасов `ZoneBot` (`permAlias`). Вручную — те же 4 скрипта по порядку и четыре алиаса:

- `^\.бот\s*(?<cmd>\S*)\s*(?<arg>.*)$` — тело из `aliases/bot.lua`;
- `^\.триг\s+(?<cmd>.+)$` — тело из `aliases/botTrig.lua`;
- `^\.пауза\s+(?<sec>[0-9]+(?:[.,][0-9]+)?)$` — тело из `aliases/botWait.lua`;
- `^botkill$` — тело из `aliases/botKill.lua` (`sendWithClear(getAttack())`, атака первой цели).

Повторная установка обновляет скрипты на месте (`setScript`) и пропускает уже существующие алиасы — дубликатов не будет. `--uninstall` отключает группу и элементы (сами элементы остаются в профиле). После установки проверка: `.бот ?` и `.бот инфо` (должны появиться VNUM, комната и выходы).

### Зоны

Записанные маршруты хранятся в репозитории в `bot/zones/*.lua` (файлы зон теперь в git). При установке установщик кладёт их в `<профиль>/bot/zones/` (каталог профиля берётся из `getMudletHomeDir()`, как у бота), сверяя дату изменения:

- файла в профиле нет или он **старее** — копируется из репозитория;
- файл в профиле **свежее** (перезаписан в игре после последней установки) — пропускается, чтобы не затереть новую запись;
- старый файл профиля перед перезаписью уходит в `<профиль>/bot/zones/backup/<зона>.lua.<дата-время>.bak` (подпапка `backup/` ботом не читается).

`--dry-run` показывает по зонам, что будет создано, обновлено или пропущено. `--uninstall` зоны не трогает. Обратной синхронизации нет: зону, записанную в игре, чтобы вернуть в репозиторий, скопируйте вручную — `cp "<профиль>/bot/zones/<зона>.lua" bot/zones/`.

Алиас атаки называется так же, как команда — **`botkill`**: бот проверяет его через `exists("botkill", "alias")` и вызывает `expandAlias("botkill")`. Если в профиле остался старый элемент `BotKill` (из первой версии установщика) — удалите его в редакторе Mudlet или оставьте выключенным, иначе команда `botkill` сработает дважды.

Нужны `mapper.lua` (MudMapper + `generic_mapper`) и `antibot.lua`: пока идёт проверка на бота, бот встаёт на паузу.

## Запись прохождения зоны

Маршрут бота — это последовательность **ходов** (`dir`, каждый помнит VNUM комнаты, в которую ведёт) и **действий** (`cmd`, выполняются в конкретной комнате). Запись делается в живом клиенте: вы ходите руками, бот фиксирует ходы и действия.

### 0. Перед записью

| Требование | Как проверить |
|---|---|
| Скрипты бота установлены | `.бот ?` печатает справку |
| MSDP работает (нужен `msdp.ROOM.VNUM`) | `.бот инфо` показывает VNUM, HP/MV, монеты |
| Бот не идёт по другой зоне | `.бот запись старт` откажется: «Бот идёт по зоне — сначала .бот стоп» |

Встаньте на **клетку прямо перед зоной** — она станет точкой входа: бот запомнит её VNUM и при запуске сам добежит сюда, создаст экземпляр зоны и начнёт проход.

### 1. Начать запись

```
.бот запись старт рр2_Пустоши
.бот запись старт башня_магов список
```

Второй аргумент задаёт **тип зоны**:

- `все` (по умолчанию) — бить всех мобов на пути;
- `список` — бить только помеченных: при проходе на нужном мобе — `.бот бить`, он попадёт в список целей зоны. Агрессоры, которые сами напали, запоминаются автоматически.

Ответ: `Запись зоны начата: рр2_Пустоши`, `Клетка входа: <VNUM>`, `Тип зоны: …`. Состояние бота становится `record`, плашка показывает `RECORD`. Бот сразу сам отправит `обл и`, чтобы узнать смежные зоны (можно набрать и руками — ответ тоже разберётся).

#### Вход в зону: что фиксируется само

Ответ на `обл и` выглядит так:

```
Наличие смежных зон:
       На юге: [472] Королевский фрегат
               Сложность макс: 2, текущая: 0, прохождений: 0
```

Из него бот берёт **направление** (`юг`), **номер и название** зоны (`[472] Королевский фрегат`) и **макс. сложность** (`2`). Если смежных зон несколько — выбирается та, в названии которой встречается имя записи (`фрегат`); иначе первая, с предупреждением и списком найденного. Клетка входа — та, где вы стояли при `.бот запись старт`.

Проверить и при необходимости поправить до сохранения:

```
.бот запись вход            # что зафиксировано
.бот запись вход + юг 2     # задать вручную: направление и макс. сложность
```

Если ответ `обл и` не пришёл, но в комнате есть строка `[Зона, на юг: …]`, направление возьмётся из неё; сложность придётся задать руками (`.бот запись вход + …`), иначе при запуске `гг !обл созда` не отправится.


### 2. Ходить по зоне

- **Одна команда за один ход**: `север`, `юг`, `восток`, `запад`, `вверх`, `вниз`; короткие формы `с`, `ю`, `в`, `з`, `вв`, `вн`; английские `n`, `s`, `e`, `w`, `u`, `d`.
- Каждый ход сохраняется вместе с VNUM комнаты, в которую привёл: подтверждение приходит событием `msdp.ROOM`.
- **Не используй `;`-цепочки, `подкрасться север`, спидвок и клики по карте.** Записываются только одиночные направления — остальное уйдёт на сервер, но в маршрут не попадёт.
- `botkill`/`kill`, `look`, чат, перевязка — не записываются (это нормально, в маршрут они не нужны).
- Если ход не подтвердился за `Bot.config.waitAfterMove` (по умолчанию 3 с), он **выбрасывается** с сообщением `Ход «север» не подтвердился — не записан`. На лагах подними ожидание:

  ```
  lua Bot.config.waitAfterMove = 5
  ```

- Ход, отклонённый сервером (`Вы не можете идти в этом направлении...`), выбрасывается.
- Закрытая дверь (`Попробуйте сначала открыть …`) ход **не выбрасывает**: двери открывают триггеры профиля (они смотрят на переменную `dir`, бот выставляет её при каждом ходе), а бот повторяет шаг. Маршрут пишется без ручного повтора.

### 3. Действия и паузы в комнатах

### `.триг` — действие

```
.триг кзаб :Барб2 все;од все
.триг вл $tempMoney;снять 500000
.триг открыть дверь
```

- Действие выполнится **в той комнате, где вы стоите сейчас**, в момент прохода по маршруту.
- Двери открывать в маршрут писать не нужно: при закрытой двери бот повторяет шаг, а открывает её профильный триггер — так же, как при ручной игре.
- После действия бот выдерживает паузу `Bot.config.waitAfterAct` (1 с) и обновляет комнату (`look краткий`).
- Действие выполняется **как ввод из командной строки**: `expandAlias`, поэтому алиасы профиля работают (`.триг оов шкаф` → `отпер шкаф;откр шкаф;взя все шкаф`). `send()` алиасы не раскрывает — раньше такая команда уходила на сервер текстом. Отключить: `Bot.config.expandActions = false`.
- Вне записи `.триг <команда>` делает то же самое — как будто команду набрали руками.
- Если набрать `.триг` до подтверждения хода, действие не потеряется: оно встанет в очередь **после** этого хода и получит комнату, когда придёт VNUM (в статусе записи это видно как «отложено»).

### `.пауза <сек>` — ожидание в маршруте

```
.пауза 3        ← подождать 3 секунды в этой комнате, потом идти дальше
```

- Это **шаг маршрута** (`{ wait = 3 }`), а не пауза бота: он выполняется при проходе в том месте, где записан.
- Дробные значения допустимы (`2,5` или `2.5`).
- Нужен для квестов: дать комнате «отработать» событие, дождаться реплики NPC и т. п.
- Пауза самого бота во время прохода — это `.бот пауза 1` / `.бот пауза 0` (другая команда, в маршрут не пишется).

### `.бот ждать <текст>` — ждать сообщение в маршруте

```
.бот ждать подвесной мост со скрипом опустился
```

- Записывает **шаг маршрута** `{ trigger = "<текст>" }`: при проходе бот стоит и ждёт, пока в строке сервера не появится этот текст (без учёта регистра), и только потом идёт дальше.
- Нужен, когда проход открывается не сразу: например, после `постучать колотушкой` мост опускается с задержкой. Фиксированная `.пауза` может не совпасть, а «ждём сообщение» срабатывает ровно по событию.
- Таймаут — `timeout` у шага или `Bot.config.triggerTimeout` (по умолчанию 10 с); если сообщение не пришло — бот останавливается с причиной.
- Пишется при записи (`.бот запись старт`), как и `.пауза`.

### 4. Следить за процессом

```
.бот запись
```

Показывает имя зоны, число записанных шагов, сколько ходов ждёт подтверждения («в очереди»), сколько действий/пауз отложено и сколько ходов потеряно.

Если «потеряно ходов» больше нуля — маршрут получится рваным (в файле не будет одного-двух переходов). Надёжнее перезаписать участок или зону целиком: ручного редактирования в боте нет, но файл маршрута — обычный Lua (см. ниже).

Быстрый ввод и спидвок шаги больше не теряют: отправленные ходы встают в очередь и подтверждаются по одному (FIFO), а действия/паузы, набранные «вперёд», ждут своей комнаты и потом встают в правильном порядке.

### 5. Закончить и сохранить

```
.бот запись стоп     # сохранить маршрут
.бот запись сброс    # выбросить запись без сохранения
```

Ответ: `Запись зоны рр2_Пустоши сохранена: N шагов` и путь к файлу:

```
<профиль>/bot/zones/<зона>.lua
```

Формат файла:

```lua
return {
  entry = { vnum = "100051", dir = "юг", maxdiff = 2,
            num = 472, title = "Королевский фрегат" },
  mode = "list",              -- "all" (по умолчанию) | "list"
  kill = {                    -- цели в режиме list (имя до глагола)
    ["Ученик магов"] = true,
  },
  aggro = {                   -- агрессоры: бьём всегда, даже в list
    ["Пещерная тварь"] = true,
  },
  noattack = {                -- мирные/квестовые: не бьём
    ["110056"] = { ["Захудалый старикашка"] = true },
  },
  steps = {
    { dir = "юг",     room = 472001 },
    { cmd = "кзаб :Барб2 все;од все", room = 472001 },
    { wait = 3,       room = 472001 },
    { trigger = "мост опустился", room = 472001 },
    { dir = "запад",  room = 472002 },
  },
  final_steps = {
    -- после маршрута; игрок уже может быть в случайной комнате города
    { cmd = "гг !путь склад" },
  },
}
```

- `entry` — вход в зону: `vnum` клетки перед зоной, `dir` (направление), `maxdiff` (макс. сложность, в файле число; в команду уходит со знаком: `maxdiff = 3` → `гг !обл созда запад +3`), `num`/`title` — для вывода.
- `mode` — тип зоны: `all` — бить всех, `list` — только `kill ∪ aggro` (см. [Два типа зон](#два-типа-зон-все-и-список)).
- `kill`/`aggro`/`noattack` — списки существ зоны; переживают повторную запись маршрута (сливаются со старыми).
- `dir` (в шагах) — ход, `room` — ожидаемый VNUM после хода, `cmd` — действие в комнате, `wait` — пауза в секундах, `trigger` — ждать строку сервера (таймаут `timeout`, по умолчанию `Bot.config.triggerTimeout`).
- `final_steps` — действия после последнего шага маршрута, когда игрок уже мог вернуться в город. Для них **не проверяются** `room` и `dir`; поддерживаются `cmd`/`wait`/`trigger`. В отличие от обычного маршрута, перед финальными действиями бот не ищет мобов. После них зона завершается и стартует следующая по очереди/кругу. Если возврат в город занимает время, добавь перед командой `{ wait = 2 }` (или нужную паузу).
- Порядок шагов = порядок выполнения. Если ход не подтвердился, его в файле не будет.
- Файл можно править руками (поправить `room`, поменять/добавить `cmd` или `wait`), но после правки проверьте маршрут (раздел 6).
- Старый формат с `transit = { vnum, portal }` тоже читается: бот просто бежит к `vnum` и идёт, без `гг !обл созда`.

### 6. Проверить маршрут

```
.бот зоны                    # все записанные зоны: имя, шаги, режим, вход
.бот маршрут рр2_Пустоши     # первые 40 шагов: команда -> ожидаемый VNUM
.бот инфо рр2_Пустоши        # шагов, вход (клетка/направление/сложность), первый и последний шаг
```

Что смотреть:

- вход: клетка перед зоной, направление и макс. сложность — из них собирается `гг !обл созда <направление> +<сложность>` (например, `гг !обл созда запад +3`);
- первый шаг должен вести из клетки входа в саму зону;
- ожидаемые VNUM идут цепочкой: `room` предыдущего шага — это комната, из которой делается следующий ход;
- действия (`cmd`) стоят в тех комнатах, где нужны.

### 7. Первый прогон

```
.бот старт рр2_Пустоши
.бот стоп
```

`.бот старт` делает три шага:

1. если вы не на клетке входа — бежит туда через `MudMapper.goto_vnum(<vnum>, "куп 2")` (то же, что `гмуть`, но по VNUM);
2. придя, отправляет `гг !обл созда <направление> +<сложность>` (например, `гг !обл созда запад +3`) и ждёт `Создан экземпляр зоны` (`Bot.config.entryWait`, по умолчанию 5 с; не дождались — идём всё равно, с предупреждением). Если сервер ответил `Вы сможете создать новый экземпляр зоны … через …`, ждать нечего: экземпляр уже существует, бот сразу идёт по маршруту. Если сервер отказал по сложности (`Для создания области зоны '…' сложности +N вы должны …`), бот пробует на 1 ниже: `+3 → +2 → +1 → обычная (без +N)` (не меняя `maxdiff` зоны); ниже `entryMinDiff` (по умолчанию 0 — обычная сложность) — стоп. Отказ вида «… сложности +1 вы должны еще 4 раза выполнить задание в области обычной сложности» тоже разбирается: после +1 бот шлёт `гг !обл созда <направление>` без аргумента сложности;
3. начинает проход по записанным шагам.

Старые маршруты с `transit` (без направления/сложности) на шаге 2 просто идут дальше.

Плашка, добивание мобов, двери, recovery и предпроверка выходов описаны в разделе [Проход](#проход); режимы отладки — в [Диагностика](#диагностика).

### 8. Если что-то пошло не так

| Сообщение | Причина | Что делать |
|---|---|---|
| `Зона «X»: нет файла ...` | имя зоны не совпало / маршрут не сохранён | `.бот маршрут X`; проверить `<профиль>/bot/zones/X.lua` |
| `Маршрут зоны «X» пуст` | запись без единого хода | перезаписать |
| `Ход «север» не подтвердился — не записан` | лаг или сервер не пустил | поднять `waitAfterMove`, повторить ход, смотреть «потеряно ходов» |
| `Запись не ведётся` | `.бот запись стоп` без старта | `.бот запись старт <зона>` |
| `Бот идёт по зоне — сначала .бот стоп` | попытка записи при запущенном боте | `.бот стоп`, затем запись |
| `маршрут устарел: «север» ведёт в 999, а в маршруте 501` | зона изменилась или маршрут записан из другой комнаты | перезаписать участок или поправить `room` в файле |
| `нет пути к комнате … (карта не промеплена?)` | целевая комната недостижима на карте | промеплить зону; либо не уходить с маршрута |

| `Ресинк по VNUM …, пропущено шагов: N` | вас перенесло/сбили, бот догнал маршрут по VNUM | проверить, что действия в пропущенных комнатах не были нужны |
| `Recovery: иду по карте к …` | бот потерял позицию в маршруте | если повторяется — перезаписать проблемный участок |
| `Не добил мобов в … — иду дальше` | 3 неудачных попытки боя в комнате | `.бот цель` (есть ли мобы и какие номера), `.бот атака` (работает ли способ атаки) |

### 9. Ограничения и тонкости

1. **Записываются только одиночные направления.** `;`-цепочки, `подкрасться север` и клики по карте в маршрут не попадут. Ходы из спидвока пишутся по одному (очередь подтверждений), но смешивать их с ручными `.триг`/`.пауза` не стоит.
2. **Просроченный ход выбрасывается**: если VNUM не пришёл за `Bot.config.waitAfterMove` (3 с), шаг не записывается и растёт «потеряно ходов». На лагах поднимайте значение.
3. **Шаг `{ wait = N }` — это пауза маршрута**, а не пауза бота: `.бот пауза` приостанавливает проход целиком и в файл не пишется.
4. **Шаги не выполняются в бою**: и действия, и паузы ждут, пока бой закончится (маршрут стоит).
5. **Ручное редактирование возможно**, но структуру (`return { steps = { ... } }`) надо сохранять: файл загружается как Lua.

## Проход

```
.бот старт рр2_Пустоши          # бег к клетке входа + «!обл созда» + проход
.бот старт зона1 зона2          # остальные зоны — в очередь
.бот стоп
.бот продолжить                  # продолжить с сохранённого шага
.бот перезагрузить «зона»       # перечитать файл маршрута с диска
.бот зоны                       # записанные маршруты: имя, шаги, режим, вход
.бот пауза 1 | .бот пауза 0     # пауза / снять паузу
```

`.бот зоны` показывает **локальные** файлы `<профиль>/bot/zones/*.lua` (имя без `.lua` можно сразу передавать в `.бот старт` или `.бот круг`). В строке зоны видны число шагов, режим `все/список`, число целей и агрессоров, вход, а также отметки `[в круге]`, `[идёт]`, `[продолжение]`. Это не серверный список экземпляров: для него остаётся `.бот обл`.

`.бот стоп` (в том числе стоп по ошибке) запоминает зону и шаг. `.бот продолжить` восстанавливает маршрут, **не создаёт экземпляр зоны заново**, сверяет текущий VNUM (стоим там, откуда делается сохранённый шаг; уже в комнате этого шага; иначе ищет комнату в маршруте) и продолжает с сохранённого шага. Точка не переживает новый `.бот старт` и конец зоны. Если текущая комната в маршруте не находится (инстанс пересоздан, зона перезаписана), продолжение отменяется с предупреждением, а точка сохраняется.

Вход в зону (`entry`) хранится в файле маршрута и фиксируется автоматически при записи: клетка перед зоной, направление и макс. сложность из ответа `обл и`. При запуске бот бежит к клетке входа (`MudMapper.goto_vnum(vnum, "куп 2")`), затем отправляет `гг !обл созда <направление> +<сложность>` и начинает проход (см. «Вход в зону» выше). Файл маршрута **перечитывается с диска** при каждом `.бот старт`, `.бот продолжить` и `.бот режим`, поэтому ручные правки `<зона>.lua` применяются без reload профиля; перечитать вручную: `.бот перезагрузить «зона»` (во время прохода этой зоны — сначала `.бот стоп`).

На каждой клетке сначала бой: если в комнате есть **красное** существо, которое не игрок, бот жмёт `botkill` (`sendWithClear(getAttack())`, цель считается как `group_count + pet_count + 1`) и ждёт боевой промпт — это нужно, чтобы начать бой и с не-агрессивным мобом. **Удар один на комнату**, число мобов в клетке не важно: повторно в этой же комнате бот не бьёт (ручной `.бот бить` можно повторять), а в процессе боя работают профильные триггеры (`встат`/`пом`). Способ атаки меняется командой `.бот атака` (см. ниже).

После боя бот делает `look краткий` и **ждёт блок комнаты** (до `lookWait`, по умолчанию 2 с), а не идёт сразу: иначе ход уходил раньше ответа на `look`, и ROOM-событие от look сбивало ожидание (desync/recovery, дубль хода). Если ответ не пришёл — идёт по таймауту.

В группе бой продолжается и после того, как у бота пропал таргет (партнёры добивают мобов). Пока в комнате есть строка существа со `сражается` или пришло `X вступил в бой на стороне Y`, бот **из комнаты не уходит**: он ждёт `Кому именно вы хотите помочь?` (так сервер отвечает на профильный `пом`, когда помогать больше некому) либо свежий `look`, который покажет, что бой закончился. `botkill` при входе в клетку при этом не блокируется — иначе бой с не-агрессивным мобом мог бы не начаться; повторно в комнате бот не бьёт. Ожидание включается, только если бот **в группе** (`group_count > 1`) или **в комнате стоит свой игрок из `assist_who`** — соло ждать некого (`groupFightRequireGroup = false` — ждать всегда). Максимум ожидания — `groupFightTimeout` (300 с). Отключить: `groupFightWait = false`; ждать только своих из `assist_who`: `groupFightAny = false`.

Recovery через `generic_mapper` требует, чтобы карта стояла в той же комнате, что и `msdp.ROOM.VNUM`. Если карта рассинхронизирована (например, комната ещё не промеплена), бот не гадает, а останавливается с сообщением:

```
Стоп: карта стоит на 110056, а вы в 110053 — включи mapping (или промепь комнату), иначе recovery невозможен
```

Направления и VNUM выходов берутся из `msdp.ROOM.EXITS` (строка `[ Exits: N E S W ]` в тексте — только маркер границы блока комнаты, из неё ничего не парсится). Перед каждым ходом бот сверяет VNUM выхода с маршрутом:

- выход ведёт в **другую** комнату → бот ищет этот VNUM в маршруте: если он там есть (динамический выход/петля), идёт туда и продолжает **с места этого VNUM** (`i = idx+1`); если VNUM в маршруте нет — стоп: `маршрут устарел: «восток» ведёт в 160017, а в маршруте 160023; комнаты 160017 в маршруте нет`. Повторные сверки в тот же VNUM ограничены `dynamicResyncLimit` (по умолчанию 3), чтобы не зациклиться: `… сверка по маршруту зациклилась`;
- выхода в `EXITS` нет (скрытый/невидимый) → предупреждение и обычная попытка хода, решение остаётся за сервером (`Вы не можете идти…` → один повтор шага, затем остановка);
- закрытая дверь (`Попробуйте сначала открыть …`) → повтор того же шага, дверь открывает профильный триггер по переменной `dir` (бот выставляет её перед каждым ходом: `север`, `запад`, для вверх/вниз — `вв`/`вн`). Повторов до `doorRetryLimit` (по умолчанию 5), потом стоп с названием двери; счётчик сбрасывается после любого успешного перемещения (смены VNUM), поэтому следующая дверь начинается с нуля. В recovery по карте из-за двери не уходим — `getPath` не проходит через закрытую дверь;
- запертая дверь (`… заперт.`) → то же: повтор шага, профильный триггер по `dir` и отпирает, и открывает. Но если сообщение про **контейнер** (`Окованный сундук заперт.`), это не дверь: бот игнорирует его, если текущий шаг — действие (`cmd`), если он не ждёт хода, или если имя похоже на сундук/ларец/ящик/сейф/шкаф. Иначе ответ на `оов сун` останавливал проход (шаг с `nil`-направлением);
- замер (`Вы замерли на месте, не в силах шевельнуться!`, паутина/стан) → это не дверь и не ошибка маршрута: бот не увеличивает `doorAttempts`/recovery, а повторяет ход после паузы `holdRetryDelay` (по умолчанию 1 с), пока не придёт новая комната. После освобождения счётчики и шаг продолжаются как обычно; остановить можно `.бот стоп`;
- ход пришёл во время боя или ожидания боевого промпта → `W.move` его не отправляет и сбрасывает старый `expect`/`deadline`; после боя `pulse` повторяет этот шаг. Без сброса бот после боя навсегда застревал на старом ожидании комнаты.

## Что бот видит в комнате

1. **Список строк комнаты** — `Bot.mobs`: всё, что пришло между `[ Exits: … ]` и концом блока. Строки фильтруются:
   - цвет каждой строки читается через `selectCurrentLine()` + `getTextFormat().foreground` (`{r, g, b}`) и классифицируется `Bot.color_kind`: **красные** — существа (мобы и игроки), **жёлтые** — предметы (считаются отдельно и в бой не идут), **серые/циановые** — проза описания и заголовок комнаты;
   - **моб — только красная строка.** Если строка не красная (серая проза, циановый заголовок/выходы, жёлтый предмет, зелёный промпт), это не цель: бот её не бьёт. Текстовый фильтр (заглавная буква + точка) остался только для явного `Bot.config.mobSource = "text"` — отладка или сервер без цветов; по умолчанию он не используется.
2. **Игрок или моб** — по имени из профиля: `assist_who` (игроки, в т.ч. согрупники). Имя игрока ищется только в **имени существа** — до первого глагола (`Bot.line_head`), иначе строка моба «Личный телохранитель короля стоит здесь, сражается с Съезо!» считалась бы игроком из-за упоминания `Съезо`. Цвет одинаковый, отличить больше нечем.
3. **Конец блока комнаты** — промпт или первая строка без цвета после цветного содержимого (мобов/предметов). Дальше идут боевые сообщения (`Вы полетели на землю от мощного удара…`) — они не становятся целями даже если красные, и блок фиксируется сразу, не дожидаясь промпта.
4. **Номер цели** — `group_count + pet_count + k`, где `k` — место существа в списке комнаты: `Bot.mobs` включает и других игроков, поэтому игрок в комнате тоже занимает номер, а моб после него сдвигается. Именно этот номер уходит в `botkill`, поэтому номера в `.бот цель` — то, что реально будет атаковано. Если существо помечено «не бью», оно всё равно занимает своё место: следующий моб бьётся своим номером, а не сдвинутым.

Проверить, что видит бот:

```
.бот цель                 # существа, игроки, group_count/pet_count и номера мобов
```

Мобы печатаются **строкой как есть** (с `(невидим)`, `...огненный щит`, «сражается с …»), игроки — коротким именем до глагола. Эвристики извлечения имени и лора в боте больше нет: для боя они не нужны, а подписи честнее показывать исходной строкой.

Строки-действия (бой, эмоции, события) в цели не попадают: `Bot.is_action_line` отбрасывает строки с уроном (`...[14]`, `(x2)`, `[ POISON ]`), строки про игрока (`Вы …`, `Вам …`) и прошедшее время действий (`ударил`, `попытался`, `промахнулся`, `произнес`, `сказал`, `умер`, `пришел/ушел`, `взмахнул`, `замерцал` …). Красная боевая строка ещё и **закрывает блок комнаты** — существа, которые шли до неё, остаются целями, а события после неё уже не считаются мобами.

## Мирные и квестовые существа

Сервер отвечает `Ваши убеждения не позволяют вам сделать этого` на атаку мирного или квестового NPC (в jmc такие отсекались флагом `[Мирный]` из лора). Бот запоминает такое существо для комнаты и больше его не бьёт — иначе он жёг ману и писал «Не добил мобов». Автоматически отказ учитывается только когда удар отправил сам бот (проход зоны или запись): ручная атака в игре при незапущенном боте правила не меняет и комнату не пропускает.

```
.бот небить          # не бить первое существо в комнате
.бот небить сброс    # снять пометки для этой комнаты
```

Список «не бить» теперь живёт **в файле зоны** — `noattack = { ["vnume"] = { ["имя до глагола"] = true } }`: если комната входит в маршрут записанной зоны, пометка сохраняется туда. Для комнат ещё не записанных зон остаётся старый общий файл `<профиль>/bot/noattack.lua` (`["vnume"] = { ["строка существа"] = true }`).

При загрузке зоны бот сам переносит из общего файла пометки её комнат в файл зоны (в буфере: `noattack → зона …: перенесено существ N`). Так, для `башня_магов` переедет `110056` → «Захудалый старикашка», а остальные комнаты останутся в общем файле до записи их зон.

В `.бот цель` такие существа помечены «(не бью — убеждения)», но **своё место в комнате сохраняют**: номер следующего моба не сдвигается.

## Два типа зон: «все» и «список»

| Тип | Кого бьёт | Типичные зоны |
|---|---|---|
| `все` (по умолчанию) | всех мобов на пути, кроме «не бить» и игроков | большинство зон |
| `список` | только цели `kill` и агрессоров `aggro` | `башня_магов` и подобные: убить конкретных мобов |

Тип задаётся при записи: `.бот запись старт «зона» список` (или `все`). Уже записанную зону можно переключить:

```
.бот режим                  # тип и счётчики текущей зоны
.бот режим все|список       # переключить текущую зону
.бот режим «зона» список    # переключить зону по имени
```

**Как наполняется список целей в режиме `list`:**

- при проходе/записи на нужном мобе — `.бот бить`: бот бьёт первое существо в комнате (номер — в `.бот цель`) и запоминает имя в `kill` зоны; файл сохраняется сразу;
- агрессоры запоминаются сами: по строкам `… напал/напала на вас`, `… атаковал … вас`, `… набросился`, `… ударил вас` и по цели из боевого промпта/MSDP (`OPPONENT_NAME`). Они попадают в `aggro` и бьются **в любом режиме**, даже если не перечислены в `kill`;
- существа из `noattack` не бьются никогда.

Имена сравниваются по «имени до глагола» (`Bot.mob_key`): `Маленький зайчик щиплет здесь травку.` → `Маленький зайчик`; короткое имя из промпта (`зайчик`) тоже находится. Регистр русских букв не важен. Если глагол в строке незнакомый, ключ режется по первому слову со строчной буквы начиная с третьего слова описания (`Ученик магов бормочет заклинание.` → `Ученик магов`).

Проверить, кого бот считает целью:

```
.бот цель     # в list-зоне у мобов пометки «(цель)» и «(мимо — не цель)»
.бот инфо     # режим, целей N, агрессоров N, не бью N
```

Если зона в режиме `список`, а цели пусты, при сохранении записи бот предупредит: драться он не будет, пока не помечен хотя бы один моб.

## Бой по номеру и способ атаки

По умолчанию бот **не знает имён мобов** и не шлёт `kill <имя>`. Он просто жмёт алиас `botkill`, а цель в нём считает профиль. Удар отправляется **один раз на комнату** — не по числу мобов: бот помечает комнату как «уже били» и не повторяет `botkill`, даже если после боя в списке остались красные строки. При переходе в другую комнату отметка сбрасывается; ручной `.бот бить` отправляет удар всегда.

```lua
-- тело алиаса botkill (создаётся установщиком, можно править)
sendWithClear(getAttack())
```

`getAttack()` / `getTargets()` (`autoAttack.lua`) берут `group_count + pet_count + i` — то есть первый моб, который был в комнате до группы (в комнате из 14 человек первый моб — №15). Если в профиле задан `setTargets("15 17")`, уйдут именно эти номера.

Способ атаки можно заменить, не трогая бота:

```
.бот атака                                   # что сейчас: режим и файл настроек
.бот атака botkill                           # дефолт: алиас botkill
.бот атака alias «мойбой»                    # любой свой алиас профиля
.бот атака команда «убить %n»                # %n = номер первой цели
.бот атака lua «sendWithClear(getAttack())»  # код; доступны Bot и target
.бот атака сброс                             # вернуть botkill
.бот бить                                     # ударить сейчас, вне маршрута (в list-зоне — запомнить цель)
```

- настройка хранится в `<профиль>/bot/attack.lua` — обычный Lua, можно править руками:

  ```lua
  return {
    mode = "command",
    template = "убить %n",
  }
  ```

- режимы: `botkill` (алиас), `alias` (любой алиас), `command` (шаблон с `%n`), `lua` (код; компилируется при сохранении — синтаксическая ошибка не применяется);
- нет ни алиаса, ни `getAttack` → запасной `kill <номер>` + предупреждение в консоль;
- `getAttack()` вернул пустую строку (антибот/пустая ротация) → команда не отправляется, попытка не тратится;
- в режиме `lua` код получает переменные `Bot` и `target` (номер цели), выполняется через `pcall` — ошибка печатается, бот продолжает работу.

## Игроки и согрупники

Мобы, другие игроки и согрупники на сервере **одного цвета** (красный) — цветом их не разделить. Поэтому:

- **игроки берутся автоматически** из глобальной таблицы профиля `assist_who` (`[имя] = имя`): в комнате игрок виден как «раса/титул + имя» (`Пещерный тролль Кофл` — это игрок `Кофл`), поэтому имя ищется в строке **отдельным словом** (`Фаэри Мералион летает здесь.` ↔ `assist_who["Мералион"]`). Такие строки не бьются и не считаются мобами;
- согрупники **не мешают бою**: `botkill` начинает отсчёт с `group_count`, поэтому их номера в цель не попадают. Именно поэтому `skipFightWithPlayer` по умолчанию **выключен** — иначе в группе бот не дрался бы вообще;
- отдельного списка «не бить» нет: игроки и согрупники определяются по `assist_who`, а `botkill` пропускает их по номеру. Если нужно не драться в комнате с людьми вообще — включите `Bot.config.skipFightWithPlayer = true`.

⚠️ Ограничение нумерации: **чужой игрок** (не из группы) в комнате сдвигает номера в ту сторону, которую знает только сервер, — `botkill` может ударить не того. Это ограничение самой нумерации, а не бота; в бою видно по `[я:хп]-[жертва:хп]` в промпте.

## Планировщики и отчёты

```
.бот зоны                       # локальные маршруты: какие имена можно ставить в круг
.бот обл                        # экземпляры зон: статус, период, остаток (команда «обл»)
.бот круг зона1 зона2 ...       # задать список и ходить, пропуская кулдауны
.бот круг + зона3               # добавить зону в круг
.бот круг - зона2               # убрать зону из круга
.бот круг                       # статус круга по данным «обл»
.бот круг стоп
```

`обл` показывает твои экземпляры: статус, номер, название, лидера, период репопа и остаток. Если зоны в этом списке нет — её можно создавать/заходить. `.бот круг` использует это:

- раз в `repopTick` (60 с), если бот свободен, отправляет один `обл`;
- идёт по списку по кругу: зоны **нет** в списке → запускает её;
- зона **есть** → пропускает, ждёт её реальный таймер из `обл`;
- `удалите вручную` → сам выполняет `обл удалить <направление>`, через пару секунд повторяет `обл` и стартует, если зона освободилась; если нет — пропускает её на `circleDeleteCooldown` (10 мин);
- если все заняты — ждёт следующего тика и проверяет снова;
- если `обл` не ответил за `instanceWait` — идёт в следующую зону списка без проверки кулдаунов.

`.бот старт` не меняется — проверок `обл` перед входом нет. Строка «Создан экземпляр зоны X.» сбрасывает данные `обл`; итог каждого прогона (время, дельта монет, число боёв) пишется в `<профиль>/bot/stats.csv`. Старая команда `.бот репоп` объединена с `.бот круг`: она предупреждает и перенаправляет аргументы в круг (`.бот репоп + зона` = `.бот круг + зона`).

## Диагностика

Если внутри тика, промпта или отложенного действия случилась Lua-ошибка, бот печатает `<red>Ошибка …: <текст>` и **продолжает работать**: тик пере-планируется в любом случае, а колбэки идут через `Bot.safe`/`Bot.later`. Раньше ошибка обрывала цепочку таймера, и бот «замирал» до ближайшего промпта — то есть до нажатия Enter.

```
.бот инфо [зона]   # состояние, комната, прогресс, сводка маршрута
.бот продолжить    # продолжить остановленную зону с сохранённого шага
.бот перезагрузить [зона] # перечитать файл маршрута с диска
.бот зоны          # локальные файлы маршрутов: шаги, режим, вход
.бот обл           # серверные экземпляры зон и таймеры репопа
.бот маршрут [зона]
.бот цель          # существа в комнате, игроки и номера для боя
.бот небить [сброс] # не бить это существо / снять список комнаты
.бот режим [зона] все|список # тип зоны: бить всех или только цели
.бот атака         # каким способом бот атакует (и файл настроек)
.бот бить          # ударить сейчас, не дожидаясь маршрута
.бот debug | dry   # подробный лог / не отправлять команды
```

## Миграция из jmc-бота

- `.botp`-маршруты jmc не содержат VNUM, поэтому их нужно перезаписать уже в Mudlet (`.бот запись старт ...`); скорость записи та же.
- Лоры мобов (`<зона>_mob.csv`) и импорт из jmc больше не нужны: бот не извлекает имена, цель считается номером (`group_count + pet_count + k`), а `.бот цель` показывает строки комнаты как есть. Списки целей зоны (`kill`/`aggro`) — это не лор: в них только имена, и они наполняются руками (`.бот бить`) и по фактам нападения.
- `BotNet.js` (обмен между инстансами через `stream.log`) не переносился.

## Настройки

Все параметры — в `Bot.config` (botCore.lua): `waitAfterMove` (ожидание ack), `waitAfterAct`, `recoverLimit`, `dynamicResyncLimit` (сколько раз сверять «выход ведёт в другой VNUM из маршрута» до стопа; по умолчанию 3), `entryMinDiff` (минимальная сложность при отказе сервера: `+3 → +2 → +1 → обычная`; `0` = обычная сложность без +N, ниже не пробуем; по умолчанию 0), `instanceWait` (сколько ждать ответ `обл`, по умолчанию 5 с), `repopUseInstances` (круг берёт реальные таймеры из `обл`; `false` — идти по списку без проверки), `circleDeleteWait` (пауза перед повторным `обл` после `обл удалить`, по умолчанию 2 с), `circleDeleteCooldown` (как долго не трогать зону с «удалите вручную», если она не освободилась; по умолчанию 600 с), `moveFailLimit`, `combatGrace` (пауза после команды атаки до боевого промпта), `combatTimeout`, `lookAfterBattle`, `lookWait` (сколько ждать блок комнаты в ответ на `look` после боя, по умолчанию 2 с), `lookEveryCell`, `groupFightWait`/`groupFightAny`/`groupFightRequireGroup`/`groupFightProbe`/`groupFightIdle`/`groupFightTimeout` (не уходить из комнаты, пока в ней идёт бой: включено, любой бой в комнате, ждать только в группе или при своём игроке в комнате (`group_count > 1` или `assist_who`), перепроверка `look` раз в 10 с после 5 с тишины, максимум 300 с), `mobSource` (`color` по умолчанию — мобы только по красному цвету; `text` — явный текстовый фильтр для отладки/сервера без цветов; старое `auto` = `color`), `expandActions` (действия из `.триг` выполнять как ввод из командной строки, с алиасами; по умолчанию `true`), `doorRetryLimit` (повторов хода в закрытую дверь, по умолчанию 5; счётчик сбрасывается при смене комнаты) и `doorRetryDelay` (пауза перед повтором, чтобы профильный триггер успел открыть), `holdRetryDelay` (пауза между повторами хода, пока персонаж замер; счётчики не расходуются, по умолчанию 1 с), `repopTick`, `skipFightWithPlayer` (не драться, если в комнате игрок; в группе не нужно), `restBelow`/`restAbove`/`restTimeout`/`standAfterRest` (отдых по выносливости), `lowHpPercent` (стоп при низком HP), `debug`, `dry`. Способ атаки — не в `Bot.config`, а в `Bot.attack` (команда `.бот атака`, файл `<профиль>/bot/attack.lua`).

Пример «беречь силы и не умирать»:

```lua
Bot.config.restBelow = 400      -- MOVEMENT ниже 400 — отдыхаем (0 = выключено)
Bot.config.restAbove = 0.85     -- до 85% от MOVEMENT_MAX
Bot.config.standAfterRest = "встать"
Bot.config.lowHpPercent = 0.25  -- HP ниже 25% — стоп (0 = выключено)
```
